== Real world examples
CIM is the IEC standard behind many modern grid projects in Europe and North America. CIM is used to turn misaligned, vendor specific data into a shared language that planners, operators, and market systems can all understand.

* European Example (1): pan European grid model exchange (ENTSO E)
** Uses CIM/CGMES to exchange transmission grid models between TSOs for regional and pan European studies: 
***  https://www.entsoe.eu/digital/common-information-model/cim-for-grid-models-exchange/
***  https://www.entsoe.eu/data/cim/cim-for-grid-models-exchange/ 
* European Example (2): smart grid applications with CIM (Denmark DSO case)
** IEEE Transactions on Smart Grid paper describing a CIM based framework (EMBARK) for integrating LV grid data to support smart grid applications at a Danish DSO.
***  https://vbn.aau.dk/en/publications/on-the-use-of-common-information-model-for-smart-grid-application/  
* North America: CIM based distribution data integration (PNNL)
** Peer reviewed framework for integrating distribution utility data using CIM and converting models into GridLAB D for planning and operations research. 
***  https://www.osti.gov/biblio/1776527 




== Where IEC 61850 fits
* Substation and device layer. IEC 61850 defines data models and services for protection, control, and automation at the substation and similar OT environments.
* Focused on IEDs, bays, and substation communication, with standardized logical nodes and fast event messaging (GOOSE, sampled values).
* Typically used by protection, SCADA, and substation engineering teams to ensure interoperable substation level behavior.
When utilities typically “need” IEC 61850
* Modernizing substation automation
* Multi vendor IED interoperability
* Fast, deterministic protection messaging
* Standardized substation data models
* Engineering/configuration tool unification
* Integrating legacy relays and new IEDs
* Transparent, future proof SCADA upgrades
* Harmonized OT semantics across sites 

== Where OpenFMB fits
* Grid edge interoperability standard. OpenFMB provides a common UML based data model and publish subscribe messaging patterns for field devices and applications at the distribution edge.
* Derived from CIM and 61850. Its information model intentionally aligns with IEC 61968/61970 (CIM) and IEC 61850 but is use case driven for distributed controls and DER coordination.
* Designed for edge computing. OpenFMB is meant to facilitate decisions “nearest to the data source,” supporting local orchestration of DERs, reclosers, regulators, and other field equipment.
When utilities typically “need” OpenFMB
* Growing DER fleets and microgrids. When many inverters, storage units, and microgrid controllers must coordinate autonomously rather than via one central SCADA/ADMS.
* Mixed protocols at the edge. When devices speak DNP3, Modbus, IEEE 2030.5, OCPP, etc., and the utility wants one semantic layer over multiple publish subscribe transports (MQTT, NATS, etc.).
* Circuit segment level automation. When distribution segments need local control logic (e.g., DER circuit segment management, feeder reconfiguration) that reacts quickly using shared edge data.
* Cybersecure, standards based peer to peer messaging. When ad hoc proprietary gateways are no longer acceptable for security, resilience, or interoperability reasons.
