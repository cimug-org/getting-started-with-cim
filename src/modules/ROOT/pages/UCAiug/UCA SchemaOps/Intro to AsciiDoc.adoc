= Intro to AsciiDoc

AsciiDoc is the technology of choice at UCAiug for producing documentation.

If you've never heard of it before, https://asciidoc.org/ is going to be a great resource as you start to learn about and use AsciiDoc. The goal here is not to duplicate information.

Another useful resource is the AsciiDoc Editor (https://asciidoceditor.com/) — an online editing tool. 

Various scripts and tools can be found around the internet to help you further. For example, Pandoc is another tool that can be used to quickly translate a word doc to AsciiDoc. A common use case is to make a standard 'template' that might have been a Microsoft Word document in the past, and then edit/combine with other resources as needed to make a full document. 

== Why AsciiDoc?

AsciiDoc is more powerful than Markdown, more open than a proprietary document format, and it is aligned with our long term vision of text-based documentats and components. It is able to manage all kinds of media, internal and external references, and other common document editing use-cases. 

It is easy to build websites with AsciiDoc. It is easy to feed text documents generated with AsciiDoc into tools, and vice versa. With this, we are able to make many reausable components. If our content is text editable, it is really easy to manage editor permissions and version control without relying on a particular link in the chain or particular technology. There is no end to the benefits.


== Other Useful Tools

CIMTool in versions 2.3+ provides some internal AsciiDoc file editing/previewing. When you use tools like these together with CIMTool builders and UML you can get some awesome autogeneration of different documents, artifacts, etc. 

== Looking Forward

UCAiug can still generate Word documents easily from AsciiDoc, if any particular standards body or use case requires it. We can also generate PDF, HTML, and much more.

With this toolchain, we should be able to replace jCleanCIM, jDocBuilder, jDocBuilder61850, and various validation tools to generate documents, validate them, and import/export into tools like IEC's OSD in the future.
