Getting Started with CIM

1. Consider

  • IP / ownership

  • Structural / flow

    • Organize by skill levels, tools, etc.

  • Pre-existing resources vs new

  • What is vendor-provided, what is CIM university, etc. vs what is published here

  • What is for cim-mg, CIMTool, vs published here

2. Goals

  • Easily navigable, digestible knowledge base

  • Extremely simple entry points

  • Reusable knowledge base / assets

  • Fewer repos/locations, simpler process

  • Clear governance, version management

  • Managed and encouraged contributions

3. Notes / Future

  • Getting involved

  • UCA, etc. History Museum

  • University Getting Started

  • Organizational / model / artifact relationships (e.g. UCA vs CGMES vs ENTSO-E vs …)

  • Jesse’s tables about UML, Profiles, artifacts, dates, owners

  • When a newcomer comes to the end of some material, point them to a vendor/utility/consultant, etc.

  • Can it be interactive? Change parameters, one-lines

  • Color coding / 'levels' / tags/hashtags / other clear organizational helpers

  • What does it mean to be compliant/conformant with the CIM? When do you "follow the standard?"
